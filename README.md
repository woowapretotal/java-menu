# 우테코 8기 최종 코딩테스트: 점심 추천 요구사항 분석 및 정리

한 주의 점심 메뉴를 추천해 주는 서비스

## 제시된 요구사항 정리 및 분석

### 입력

- 메뉴 추천을 받을 코치의 이름을 입력받는다. (프롬프트 포함)
    - 입력 예외 검증: 올바른 값이 아닌 경우
    - 판단: 코치의 인원 수? 이름의 길이?
- 각 코치가 못 먹는 메뉴를 입력받는다. (프롬프트 포함)
    - 판단: 메뉴의 개수? 메뉴의 이름 길이?

### 출력

- 서비스 시작 문구 출력
- 서비스 종료 문구 출력 (메뉴 추천 결과)
    - row: 코치 이름
    - column: 요일와 매핑된 카테고리
- 예외 상황 시 에러 문구를 출력해야 한다. 단, 에러 문구는 "[ERROR]"로 시작해야 한다.

### 검증

- 코치의 이름은 최소 2글자, 최대 4글자이다.
- 요일은 월~금이다.
- 코치는 최소 2명, 최대 5명까지 식사를 함께 한다.
- 각 코치는 최소 0개, 최대 2개의 못 먹는 메뉴가 있다.
    - 먹지 못하는 메뉴가 없으면 빈 값을 입력한다.
- 한 주에 같은 카테고리는 최대 2회까지만 고를 수 있다.
- 각 코치에게 한 주에 중복되지 않는 메뉴를 추천해야 한다. (중복되지 않아야 한다.)
- 입력한 메뉴가 존재하는지 검증해야 한다

### 기능

**메뉴 추천**

- 로직
    - 월요일에 추천할 카테고리를 무작위로 정한다.
    - 각 코치가 월요일에 먹을 메뉴를 추천한다.
    - 화, 수, 목, 금요일에 대해 i, ii 과정을 반복한다.

예시)
구구: 비빔밥, 김치찌개, 쌈밥, 규동, 우동 → 한식을 3회 먹으므로 불가능
토미: 비빔밥, 비빔밥, 규동, 우동, 볶음면 → 한 코치가 같은 메뉴를 먹으므로 불가능
제임스: 비빔밥, 김치찌개, 스시, 가츠동, 짜장면 → 매일 다른 메뉴를 먹으므로 가능
포코: 비빔밥, 김치찌개, 스시, 가츠동, 짜장면 → 제임스와 메뉴가 같지만, 포코는 매번 다른 메뉴를 먹으므로 가능

### 시스템 요구사항

**카테고리 구현 로직**

- 추천할 카테고리는 camp.nextstep.edu.missionutils에서 제공하는 Randoms.pickNumberInRange()에서 생성해 준 값을 이용하여 정해야 한다.
- 임의로 카테고리의 순서 또는 데이터를 변경하면 안 된다.
    - Randoms.pickNumberInRange()의 결과가 1이면 일식, 2면 한식, 3이면 중식, 4면 아시안, 5면 양식을 추천해야 한다.
- 추천할 수 없는 카테고리인 경우 다시 Randoms.pickNumberInRange()를 통해 임의의 값을 생성해서 추천할 카테고리를 정해야 한다.

**메뉴 추천 구현 로직**

- 추천할 메뉴는 정해진 카테고리에 있는 메뉴를 camp.nextstep.edu.missionutils에서 제공하는 Randoms.shuffle()을 통해 임의의 순서로 섞은 후, 첫 번째 값을 사용해야 한다.
    - 카테고리에 포함되는 메뉴 목록을 List<String> 형태로 준비한다.
    - `String menu = Randoms.shuffle(menus).get(0);`
- 임의로 메뉴의 순서 또는 데이터를 변경하면 안 된다.
    - Randoms.shuffle() 메서드의 인자로 전달되는 메뉴 데이터는, 최초에 제공한 목록을 그대로 전달해야 한다.
    - 코치에게 추천할 메뉴를 정할 때 이미 추천한 메뉴, 먹지 못하는 메뉴도 포함된 리스트를 전달해야 한다.
- 추천할 수 없는 메뉴인 경우 다시 섞은 후 첫 번째 값을 사용해야 한다.

- 사용자가 잘못된 값을 입력할 경우 IllegalArgumentException를 발생시키고, "[ERROR]"로 시작하는 에러 메시지를 출력 후 그 부분부터 입력을 다시 받는다.
- Exception이 아닌 IllegalArgumentException, IllegalStateException 등과 같은 명확한 유형을 처리한다.

## 유즈케이스 정리

- 코치 이름을 등록한다.
- 각 코치가 못 먹는 음식을 등록한다.
- 메뉴를 추천한다.

## 비즈니스 로직 정리

- 코치 이름을 등록한다.
    - 코치의 이름과 인원을 검증한다.
- 각 코치가 못 먹는 음식을 등록한다.
    - 음식이 존재하는지 검증한다.
    - 음식의 수를 검증한다.
- 메뉴를 추천한다.
    - 카테고리를 정한다.
    - 각 카테고리에 해당하는 메뉴를 정한다.

## Layer 구분

### MenuSelectDispatcher(Presentation Layer)

- 사용자가 선택한 메뉴를 처리할 수 있는 Controller를 찾아 처리하도록 합니다.(dispatch)

### Controller(Presentation Layer)

- 사용자 요청을 받아 유즈케이스를 처리하고, 그 결과를 사용자에게 반환합니다.

### ConsoleInputAdapter(Presentation Layer)

- 사용자 입력을 Application이 처리할 수 있는 형태로 변환합니다.
- 입력을 위한 콘솔 프롬프트를 담당합니다.

### Application Service

- Application이 처리하는 유즈케이스를 담당하고, 비즈니스 로직 오케스트레이션 및 트랜잭션 경계를 담당합니다.

### Domain Service

- 도메인 객체 생성 및 도메인 로직 수행을 담당합니다.
- Bounded Context를 넘어가거나 여러 도메인 객체가 협력해야 하는 로직을 담당합니다.
